## Outcome Summary

Hyprland 0.55+ deprecated hyprlang config and 0.57 will remove it. The repo's generated Hyprland configuration is now fully Lua: `~/.config/hypr/hyprland.lua` requires `custom/{env,execs,general,rules,keybinds}.lua`, `workspaces.lua`, `monitors.lua`, all generated by `modules/desktop/hyprland.nix` via the `hl.*` API. `custom/variables.conf` was removed (values inlined from Nix). `modules.desktop.hyprland.extraConfig` now carries Lua and all consumers (axiom, azar, ramen, udon, autumnal theme) are converted. `hypridle.conf` stays hyprlang because hypridle is unaffected by Hyprland's config format removal.

当前有效结论：仓库内不再存在任何 Hyprland hyprlang 配置；新贡献一律写 Lua（`hl.bind` / `hl.config` / `hl.monitor` / `hl.window_rule` / `hl.layer_rule` / `hl.workspace_rule` / `hl.on("hyprland.start")`）。验证链为渲染生成文件 + `luac -p` + 全 closure build；live session 检查（warning 消失、keybind、startup 顺序）为部署后 smoke，记录在本任务 raw docs 的 residual 清单。

## Reusable Decisions

- Hyprland 配置生成与宿主扩展点（`extraConfig`）现在只接受 Lua；不要再向任何 hypr 路径写 hyprlang 语句。
- `$var` 变量在 Lua 配置中不存在；生成值由 Nix 直接内联，不要再引入 variables 文件。
- bind 语义映射固定为：bindl → `{ locked = true }`，bindr → `{ release = true }`，bindm → `{ mouse = true }`。
- 生成的 `hyprland.lua` require 顺序 = 旧 source 顺序（env → execs → general → rules → keybinds → workspaces → monitors），依赖 `hyprland.start` handler 的注册顺序。
- `hypridle.conf`、`xdph.conf`、runtime `hyprctl keyword` 路径不受本次迁移影响，保持 hyprlang/不变。
- 部署前必须渲染生成文件并跑 `luac -p`；部署后 smoke：`hey reload` 后 Hyprland log 无 `.conf` 弃用 warning。
